# Протокол тестирования

Чек-лист, который проходится перед выпуском беты и стабильной версии. Он покрывает сервер, веб-панель, десктопный GUI, Android-клиент и CLI-клиент.

Как пользоваться:

- У каждого случая есть номер, шаги и ожидаемый результат. Случай пройден, только если результат совпал полностью.
- **P1** — обязательно для беты и стабильной версии. **P2** — обязательно для стабильной версии, для беты по возможности.
- Если что-то не совпало, заведите issue с номером случая, версией, платформой и логом. Отчёт о прогоне заполняется по шаблону в конце документа.
- Сертификаты сначала проверяются на staging Let's Encrypt (`--staging`), и только потом на боевом CA: у боевого жёсткие лимиты на неудачные выпуски.

## 1. Стенд

- **Сервер:** VPS на Debian 12 или Ubuntu 24.04 с публичным IPv4 (желательно и IPv6). Домен с A-записью (и AAAA) на этот сервер. Порты 80, 443 и 50000 (TCP+UDP) открыты.
- **Веб-серверы для раздела 2.4:** отдельные чистые машины или снапшоты с nginx, apache (Debian и RHEL-семейство) и caddy.
- **Клиенты:** Windows 10/11 x64 (arm64, если есть), Android 8+ на arm64 и armv7, Linux x64 для CLI.
- **Сети:** домашний провайдер, мобильная сеть, по возможности IPv6-only сеть с NAT64 и сеть с заметной DPI-фильтрацией.
- Версия каждого компонента записывается в отчёт (`ostp --version`, «О программе» в GUI, версия APK).

## 7. Критерии выпуска

- **Бета:** все случаи раздела 0 и все P1 пройдены. Непройденные P2 перечислены в заметках к релизу как известные проблемы.
- **Стабильная версия:** пройдены все случаи, включая P2, на всех платформах из раздела 1.
- Любой краш, потеря профилей или ключей, утечка ключа в лог или трафик мимо туннеля при включённом kill switch — блокер независимо от приоритета.
